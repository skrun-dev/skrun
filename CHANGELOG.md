# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-08-30

### Breaking
- **Agents are private by default; `POST /run` is now run-authorized.** A `private` agent (the new default) runs only for its owner or an instance admin — any other caller gets a `404` indistinguishable from a missing agent, closing the cross-tenant run exposure. This replaces the previous behavior where any authenticated caller could run any verified agent in any namespace (the 0.8.0 "running an agent stays cross-namespace" note). Agents are **private-only** in this release — the `public` set-path is disabled (`public` ships with the marketplace), so there is no per-agent open-access escape hatch for now. Existing agents are migrated to `private` on upgrade. The per-run `environment` override is now owner/admin-only — a non-owner who supplies one gets `403 ENV_OVERRIDE_FORBIDDEN`, so a caller can no longer widen a creator's declared `allowed_hosts`. Whether a private agent's version must be verified to run is now an **operator choice** (`SKRUN_VERIFICATION_POLICY`, default `admin` = the legacy gate; `owner` lets creators self-attest) — see Added below.
- **The server's own LLM key is no longer sent to an agent-declared `model.base_url`.** An `agent.yaml` may point the model call at an alternative OpenAI-compatible provider or a local inference server. When no caller or creator key was available, the server previously fell back to its own `<PROVIDER>_API_KEY` and sent it there — so on a host running agents written by other people, an agent author could direct the operator's credential at a host of their choosing. That pairing is now opt-in: set `SKRUN_ALLOW_SERVER_KEY_CUSTOM_BASE_URL=true` only where every agent is authored by the operator. Otherwise attach a creator key to the agent or pass one via `X-LLM-API-Key`; the refusal names all three routes. This contradicts what `docs/agent-yaml.md` previously documented, which has been rewritten.
- **A caller-supplied `X-LLM-API-Key` is refused when the agent declares a `model.base_url` you did not name.** If you run someone else's agent with your own LLM key — the delegated-key case, where a creator issues you an agent-scoped `sk_live` — the agent's author chooses the destination while you supply the credential. Declare the endpoint your key belongs to in the new `X-LLM-Base-URL` header (same `{provider: url}` shape, compared by origin so the path need not match) and the run proceeds; omit it and you get `403 CALLER_BASE_URL_NOT_CONSENTED`, whose message names the agent's origin so you can decide. **Running your own agent with an account-wide credential — a session, a `dev-token`, or a full `sk_live` — is unaffected**, as is any agent that declares no `base_url`. SDK: the new `llmBaseUrls` option on `run()` / `stream()`.
- **The Docker Compose self-host stack no longer has default credentials.** `POSTGRES_PASSWORD`, `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` had `:-` fallbacks (`skrun-dev-only`, `minioadmin`), so `docker compose up` with an empty `.env` booted Postgres and MinIO on credentials published in this repository. The stack now **refuses to come up** rather than pick credentials for you: a `preflight` container checks the three variables and stops everything with a message naming the missing one. It exists because the images disagree about what empty means — Postgres refuses an empty password on its own, while MinIO treats an empty `MINIO_ROOT_USER` as *unset* and boots on `minioadmin:minioadmin`, so the stack refuses on its behalf. A CI job asserts this per service on every change. Generate them (`openssl rand -hex 16`) and put them in `.env` — the quickstart in `docs/self-hosting-docker.md` shows the one-liner. The **minimal** overlay (`docker-compose.minimal.yml`, SQLite + local disk) needs none of them and is unchanged.
- **Cloud `DATABASE_URL` secret format change.** Operators must update Fly's `DATABASE_URL` secret from the Supabase HTTPS Project URL (`https://<ref>.supabase.co`) to a standard `postgres://` connection string — recommended: the Supabase **Session** Pooler URL on port 5432 (Project Settings → Database → Connection string → Session pooler) — transaction mode on port 6543 breaks the `pg_advisory_lock` the migrations-runner takes for concurrent-boot safety. `SUPABASE_KEY` secret can be `flyctl secrets unset` (no longer used — the URI embeds credentials). Update it with `flyctl secrets set DATABASE_URL='postgres://…'`, then `flyctl secrets unset SUPABASE_KEY`. The api-server validates the prefix at boot and refuses to start with a stale HTTPS value.

### Added
- **Cloud runtime — `SKRUN_RUNTIME=flyio`.** Each `POST /run` now spawns a dedicated Fly.io sandbox machine when the server runs in `flyio` mode. The harness drives the LLM loop and holds every credential (LLM keys, DB, S3, webhook signing); the sandbox runs agent code with **zero** credentials, a read-only rootfs, non-root UID 1000, every Linux capability dropped, and an iptables egress allowlist that re-resolves short-TTL hosts every 30 s. Machines are destroyed in a `finally` block + on caller SSE disconnect; orphans are reaped by the new `skrun admin cleanup-machines` (see below). Toggle via `SKRUN_RUNTIME` env var — `local` (default) keeps every run in-process. Full env-var list documented in `.env.example` and `docs/api.md`. Closes the long-standing "cloud delivery" gap from the original blueprint.
- **Multi-runtime sandbox image (`ghcr.io/skrun-dev/skrun-runtime`).** Ubuntu 24.04-based image with Python 3.12, Node 22, Go 1.22, Rust 1.77, Ruby 3.3, Java 21, PHP 8.3 baked in via `mise` + `apt`. Aligned with Anthropic's `agent_toolset_20260401` so Skills written for Claude Managed Agents run unmodified on Skrun. Published linux/amd64 + linux/arm64 to GHCR on every `v*.*.*` tag via `.github/workflows/runtime-image.yml`.
- **Docker Compose self-host stack (`infra/docker-compose.yml`).** One-command prod-parity self-host: API + Postgres + MinIO + Redis + Caddy with all sandbox hardening controls on by default (read-only rootfs, non-root UID, cap-drop ALL, no-new-privileges). Caddy's `flush_interval -1` is configured for SSE-safe reverse proxying. Minimal override (`infra/docker-compose.minimal.yml`) drops Postgres/MinIO/Redis for single-operator deployments using SQLite + LocalStorage. New guide: `docs/self-hosting-docker.md`.
- **`skrun admin cleanup-machines` CLI.** Operational command for cloud-runtime operators — reaps orphan Fly.io sandbox machines that survived rare destroy failures. Conservative defaults (`skrun-run-*` prefix only, age > 600 s = 2× `MAX_RUN_TIMEOUT_S`, partial-failure continuation), `--dry-run` preview mode, machine-readable PASS line for cron scripts. Requires `FLY_API_TOKEN` + `FLY_APP_NAME`.
- **`run_heartbeat` SSE event.** Periodic keep-alive emitted every ~30 s during slow upstream waits — LLM call (`stage: "waiting_llm"`), tool dispatch (`waiting_tool`), or cloud-mode outputs upload (`uploading_outputs`). Prevents reverse-proxy / load-balancer idle-timeout closures on long agent runs. Fully informational — clients that already ignore unknown event types (per the SSE spec) get it for free; clients that pattern-match on event types should add a no-op handler. Documented in `docs/api.md`.
- **Structured log on every sandbox machine spawn / destroy.** Cloud mode emits Pino `info` lines `event: "spawn_ready"` (carrying `run_id`, `machine_id`, `tool_count`) at successful boot and `event: "machine_destroy"` (carrying `machine_id`, `reason`) at teardown. The `reason` discriminates lifecycle paths: `run_complete` / `run_error` / `timeout` / `aborted` / `run_failed` / `spawn_failed_create` / `spawn_failed_boot-probe` / `spawn_failed_init-rpc`. Pipe stdout to your log aggregator and filter on the event names — the forensic trail for cloud-runtime billing reconciliation + leak detection until a dedicated audit-log surface ships. The `skrun admin cleanup-machines` summary line (`PASS cleanup-machines: scanned=N cleaned=M`) is the matching reaper telemetry.
- **`run_complete.files[]` entries gain a `url?` field in cloud mode.** When `SKRUN_RUNTIME=flyio` is active, the harness sync-uploads each output file to R2 / MinIO and presigns a short-lived (~15 min) GET URL embedded in the `run_complete` event payload — direct download from object storage, no API proxy hop. Self-host (`SKRUN_RUNTIME=local`, default) leaves `url` unset; consumers continue to fetch via `/api/files/:id/content` as before. Additive — existing SDK / CLI callers that ignore unknown fields keep working unchanged.
- **The published runtime image now serves the operator dashboard at `/dashboard`.** Previously the Docker image was API-only and the dashboard was reachable only from a bare-metal install; the image now bundles the built dashboard SPA and serves it in `api-server` mode — same console, same origin as the API. Set `SKRUN_DASHBOARD=off` (or `false`/`0`) for a headless, API-only deployment; `SKRUN_DASHBOARD_DIR` overrides the served directory. Documented in `.env.example` and `docs/self-hosting.md`.
- **Per-agent visibility controls (private-only).** New `agent.visibility` (`private` default / `public`) governing run-authorization: a `private` agent runs only for its owner/admin. The **set-path is private-only for now** — `PATCH /api/agents/<ns>/<name>/visibility` (and `skrun visibility <ns>/<name> private`, `client.setVisibility(agent, "private")`) accept `private` and reject `public` with `400 PUBLIC_VISIBILITY_DISABLED`; the dashboard shows a read-only visibility badge (no public toggle). `public` is a marketplace capability — the column and the run-authorization branch are retained, so it reactivates without a migration. See `docs/concepts.md` → "Visibility & access".
- **Configurable verification policy (`SKRUN_VERIFICATION_POLICY`).** Operators choose who may attest an agent version and whether runs are gated on verification: `admin` (default — instance admins only, an unverified version returns `403 AGENT_NOT_VERIFIED`; the legacy behavior, so an unset value changes nothing), `owner` (the agent owner may self-attest their own agents and a private agent runs without the gate — for multi-tenant hosting where one operator can't vet everyone), or `disabled` (no gate). The policy is read once at boot — an invalid value fails the boot fast, and changing it requires a restart. The active policy is surfaced read-only on `/api/me` (for the dashboard's verify control), and every attestation logs a `kind` (`admin` / `owner_self`) for the forensic trail. See `docs/self-hosting.md` → "Verification policy".
- **Enforced API-key scopes (operation + resource).** API keys now carry an enforced **operation** scope (`agent:run` / `agent:push` / `agent:verify` — previously inert) and a **resource** scope (`scope_kind`: `account` default, or `agents` bound to specific agents you own). A creator can mint a **run-only key scoped to one agent** and give it to a client, who runs that agent — and nothing else — without a Skrun account (the "restricted key" pattern): no other agents, no source pull, no run history, no key management, all `403 KEY_SCOPE_FORBIDDEN`. Account-management actions require an account-wide full key, so a restricted key can't escalate; account-wide keys, sessions, and `dev-token` are unchanged. Create scoped keys from the dashboard or `skrun keys create`; runs record the calling key (`runs.api_key_id`) for per-key metering. See `docs/concepts.md` → "API-key scopes".
- **Creator-attached LLM keys + caller-key policy.** An agent's owner can attach their **own** LLM key to the agent (encrypted at rest with AES-256-GCM under `SKRUN_SECRETS_ENCRYPTION_KEY`) so their callers run it **without supplying a key** — the creator pays the inference. Keys resolve per provider in the order **caller (`X-LLM-API-Key`) > creator > server**, composing with the existing model→fallback. A new per-agent `llm_key_policy` (`open` default / `creator_only`) lets the owner reject caller-supplied keys — a run carrying `X-LLM-API-Key` then gets `403 CALLER_KEY_NOT_ALLOWED`. Keys are **write-only** (reads expose only the provider + last4, never the key). Manage via `PUT/DELETE/GET /api/agents/<ns>/<name>/llm-keys[/<provider>]` + `PUT …/llm-key-policy`, the new `skrun llm-key set/list/rm/policy` CLI (key read from stdin or `--key-env`, never an argument so it stays out of shell history), or the agent-detail dashboard. Self-host sets `SKRUN_SECRETS_ENCRYPTION_KEY` (`openssl rand -base64 32`) to enable attaching. See `docs/concepts.md` → "LLM keys".
- **Optional pre-warm pool for cloud runs (`SKRUN_RUNNER_POOL_SIZE`).** A cloud run's first output used to wait most of a minute while a sandbox machine was created, its image pulled and its runner started. The server can now keep a few machines built, booted and paused ahead of time; a run wakes one instead of building one. Measured on a deployed instance: **~53 s → ~1.3 s** before the agent starts, on the same code and the same app with the pool switched off and on. **Off by default** (`0`), and off means unchanged — the pool is never constructed and every run takes the path it takes today. Isolation is unchanged too: a pooled machine is built **blank** (no bundle, no run credential, no agent network rules), receives them only when a run claims it, serves **exactly one** run and is destroyed — a stock of never-used machines, not of recycled ones. An empty pool is not an error: the run builds its own machine as before. Deploys drain the pool automatically, since a machine built from a superseded image is destroyed rather than used — which is also what makes rolling an image back uneventful. New admin-only `GET /api/admin/pool` exposes depth, hit rate and failure counters, and cloud runs report `pool_hit` plus the wake/claim timings on the existing `runner_spawned` event. See `docs/self-hosting.md` → "Pre-warm pool".
- **Per-phase startup breakdown for cloud runs (`runner_spawned` event + `phase_timings`).** Each cloud (`SKRUN_RUNTIME=flyio`) run now reports where its startup time went — the Fly machine `create` call, the host-side schedule + image pull (derived from the machine's own boot clock), the in-machine boot + egress setup, and the `/init` steps (bundle download, extract, MCP connect). The breakdown is emitted once as a `runner_spawned` SSE event (durations only) right after `run_start`, and persisted on the run record as `phase_timings`. This turns the previously-silent ~50-60 s gap on a first cloud run into data, so an operator can see whether a slow start is the image pull or something else. The runner's machine id + private IP are recorded operator-side but are **not** returned by `GET /api/runs/:id`. Additive — SSE clients that ignore unknown event types are unaffected (add a no-op handler if you pattern-match on event types). Local runs (`SKRUN_RUNTIME=local`, the default) don't spawn a machine, so they carry no breakdown. See `docs/api.md` → "Run events".

### Changed
- **Self-host docker-compose stack now boots end-to-end.** The 0.9.x release shipped `infra/docker-compose.yml` with a "known follow-up" disclaimer — the api package's `SupabaseDb` could not talk to the local `postgres:5432` service. Replaced internally with `PostgresDb` (direct `pg` driver, raw SQL) — any Postgres ≥ 14 works (Supabase / Fly Postgres / RDS / Neon / Render / local docker-compose). Migrations apply automatically on api-server boot with `pg_advisory_lock` concurrent-safety. `@supabase/supabase-js` (+8 transitives) dropped from the lockfile.
- **`StorageAdapter` interface extended additively.** New `getPresignedDownloadUrl(key, expiresIn)` + `getPresignedUploadUrl(key, expiresIn)` + `put(key, data)` methods so the cloud `FlyioAdapter` can hand presigned URLs to sandbox machines (which hold zero S3 credentials) and sync-upload outputs to R2 / MinIO after each run. `MemoryStorage` and `LocalStorage` throw the new `NotSupportedError` on presigned-URL calls (they don't need them — those backends serve files via the existing `/api/files/:id/content` proxy), keeping the self-host path zero-impact. `R2Storage` (new — built on `@aws-sdk/client-s3`) implements every method against either Cloudflare R2 or MinIO depending on the `S3_ENDPOINT` env (toggle for self-host MinIO vs cloud R2). Non-breaking for callers — the new methods are additive to the interface; only cloud-runtime wiring requires them.
- **LocalAdapter LLM loop refactored.** Extracted into a shared `runAgentLoop` helper (`packages/runtime/src/adapter/agent-loop.ts`) consumed by both `LocalAdapter` and the new `FlyioAdapter`. `runAgentLoop` is an `AsyncGenerator` that yields RunEvents in real time (instead of collecting and returning at end), which is what makes `run_heartbeat` actually flush through SSE during the wait. Behaviour-preserving — all 392 prior LocalAdapter tests continue to pass.
- **`skrun login` uses a browser device flow.** The interactive login (no `--token`) now prints a one-time code + URL, opens your browser, and polls for the token (OAuth 2.0 Device Authorization Grant, the same pattern as `gh`/Vercel) instead of running a local callback server. **An old CLI binary can no longer complete an interactive login against an updated server** — it gets an "update your Skrun CLI" page; run `npm i -g @skrun-dev/cli`. `skrun login --token …` and `dev-token` mode are unchanged. Optional `SKRUN_DEVICE_CODE_TTL_S` (default 600 s) tunes the code lifetime.
- **`max_cost` is now enforced, not just logged.** An agent's `environment.max_cost` ceiling previously only emitted a warning when crossed — the run continued and completed. The runtime now aborts the run as soon as the aggregate estimated cost crosses the ceiling, ending it with a `run_error` carrying code `COST_EXCEEDED` and **no** `run_complete`; partial usage up to the abort is still summed into the terminus event. Agents that declare no `max_cost` are unaffected.
- **The `.agent` bundle archiver moved to a single maintained tar library.** The CLI (`skrun build`) and the server-side "push from directory" path previously each built and parsed the bundle's tar archive with hand-written code; they now share one well-tested implementation. The on-disk format is unchanged — bundles published by older versions still install. One CLI behaviour changes: **`skrun pull` now fails with an extraction error if a bundle contains a symbolic link or a path that escapes the target directory**, instead of silently dropping those entries. Bundles are also byte-for-byte deterministic now, so re-publishing unchanged sources produces an identical archive.
- **Run and run-file reads return an opaque `404` (not `403`) to non-owners.** `GET /api/runs/:id` and `GET /api/runs/:run_id/files/:filename` now return the same `404` for a run you don't own as for a run that doesn't exist, so a caller can't use the status code to tell whether another user's run exists — matching the opaque reads already used elsewhere in the registry. Reads by the owner are unchanged, and the `403` returned to a resource-scoped (delegated) key is unchanged (it's about key scope, not existence).
- **Clearer error when calling a cloud agent in one-shot mode.** A single-response call (`skrun run` / `SDK.run()`) against the `flyio` cloud runtime raised a cryptic internal message; it now returns an actionable error explaining that one-shot execution isn't wired on the cloud runtime and to use streaming instead (the dashboard Run button, `SDK.stream()`, or an `Accept: text/event-stream` request).
- **The cloud sandbox image is split into a slim runner + the full self-host image, and served from a co-located registry.** The multi-runtime image now builds two variants from one Dockerfile: a **slim runner** image for cloud execution — it omits the API-server bundle, the operator dashboard, and the compiler toolchain that a sandboxed run never uses (~16% smaller) — and the **full image** that self-host keeps (`docker compose` still pulls the complete image, with the dashboard and the native-dependency build tools intact). On the cloud, the runner image is additionally served from Fly's own co-located registry rather than pulled from an external registry over the public internet, so a first-run machine fetches it faster. **Self-host is unaffected** — the `:latest` / `:edge` tags remain the full image. The net effect is a shorter delay before the first output of a cold cloud run, with no change to what a run can do.

### Fixed
- **GitHub OAuth login now works behind a TLS-terminating reverse proxy.** The OAuth `redirect_uri` (and the OpenAPI `servers` URL) were built from the request as seen *inside* the proxy — i.e. `http://…` — even though the public site is `https://…`. GitHub rejects a callback whose scheme doesn't match the one registered for the OAuth app ("Invalid Redirect URI"), so sign-in failed on every HTTPS deployment (cloud, or self-host behind Fly / Caddy / nginx / Cloudflare); it only worked on a plain-HTTP `localhost`. Externally-facing URLs are now derived from the standard `X-Forwarded-Proto` / `Host` headers, falling back to the request's own scheme for direct access.
- **Dashboard stats are correct on Postgres-backed instances.** Three fixes to the operator console's metrics. (1) The **7-day view and every sparkline** rendered all-zero on a Postgres database — the per-day aggregation mishandled the database driver's `date` type and dropped every bucket; charts now populate (SQLite / in-memory self-host was never affected). (2) The **"24h" and "7d" tiles are now true rolling windows** (the trailing 24 hours / 7 days) instead of "since 00:00 UTC" — a run from a few hours ago no longer drops out of the count when it lands on the previous UTC calendar day, and the window no longer shifts with the viewer's timezone. (3) The **agent count is now scoped to the signed-in user** on multi-tenant instances, consistent with the per-user run / token / cost metrics (it previously showed the instance-wide total).
- **Cloud runs no longer fail with "manifest unknown" on a fresh deployment.** The sandbox image now publishes a moving `:edge` tag on every build (always resolvable), and the api-server fails fast at startup if `RUNTIME_IMAGE_TAG` is unset in `flyio` mode instead of silently defaulting to a `:latest` tag that may not exist yet. See `docs/self-hosting.md` for the image-tag guidance.
- **A batch of robustness fixes from the 2026-06 internal audit.** The device-token poll now guards against a since-deleted account — it consumes the pending code and returns `expired_token` rather than minting a token for a user that no longer exists. The best-effort cleanup paths (orphan-bundle delete, last-used-at update) now log a structured `warn` on failure instead of swallowing the error silently, so operators see them in the log drain. Internally, the seven duplicated account-wide-key authorization guards across the auth / registry / llm-key routes were consolidated behind one shared helper with a single canonical message, and the MCP client handle is now strongly typed.
- **Agent bundles built on Windows now run on Linux.** A bundle packaged on a Windows machine stored file paths with backslash separators, so on a Linux runner the agent's `scripts/` directory didn't exist and its scripts were reported "not found". Bundle paths are now always normalised to forward slashes regardless of the machine that built them.
- **The server-side "push from directory" path no longer ships virtualenvs, and binary files survive extraction.** The dashboard's build-and-push used a shorter exclude list than `skrun build`, so an agent pushed that way could bundle its `venv/`, `.venv/`, `__pycache__/`, or `.pytest_cache/` directories; both paths now share the same exclude list. Separately, binary files inside a bundle (images, fonts, spreadsheet/deck templates) are now written to disk byte-for-byte on the server instead of being round-tripped as UTF-8 text, which could corrupt them.
- **TypeScript (`.ts`) agent tool scripts now run on the runner.** A tool implemented as a `.ts` script failed to execute — the runner launched it with plain `node`, which rejects a `.ts` file, so the tool call errored with `ERR_UNKNOWN_FILE_EXTENSION`. `.ts` scripts now run through Node's native type-stripping, on both the local runtime and the cloud runner; `.js` and Python scripts are unchanged.
- **Faster fallback when the primary model stops responding.** When an agent declares a fallback model and the primary provider hangs, the runtime now switches to the fallback after a short timeout (default 45 s, tunable via `SKRUN_PRIMARY_FAILOVER_MS`) instead of waiting on the provider SDK's much longer internal timeout. No effect when no fallback is configured.
- **`skrun admin cleanup-machines` no longer destroys machines a server is keeping ready.** Where the server keeps a pool of pre-created machines, the reaper treated an idle one as reclaimable once it passed the age cutoff — reasoning, correctly, that a suspended machine cannot have a run on it. Correct, and beside the point: that machine is the unused stock the pool exists to hold. On the five-minute schedule this page recommends, the reaper emptied the pool on every pass; no run ever broke, the pool simply refilled, and the feature stopped paying for itself. Pre-created machines (`skrun-pool-*`) are now skipped at any age — they belong to the server that created them, which recycles them itself — and the command says so rather than skipping silently. Pass the new `--include-pool` when decommissioning a deployment; even then, a machine that could be serving a run is refused.
- **`skrun admin cleanup-machines` can no longer sweep the wrong Fly app.** The command took its app name from `FLY_APP_NAME` while the API server takes it from `SKRUN_RUNNERS_APP` — and Fly sets `FLY_APP_NAME` inside every machine to *that machine's own* app. A cleanup scheduled on a Fly machine (the pattern the docs recommend) therefore swept the app it ran in, found no sandbox machines, and reported a perfectly healthy `scanned=0 cleaned=0` while real orphans accumulated elsewhere. The app now resolves as `--app` → `SKRUN_RUNNERS_APP` → `FLY_APP_NAME`, so the CLI and the server agree on one name; the legacy variable still works but the command says so when it falls back. New `--app` / `--token` flags override the environment outright, and the machine-readable `PASS` line now carries `app=<name>` — the piece that lets you tell "nothing to clean" apart from "wrong target".
- **Webhook delivery can no longer hang indefinitely.** The outbound webhook request now has a bounded per-attempt timeout, so an endpoint that accepts the connection but never responds no longer ties up a background task through the retry loop.
- **`X-LLM-API-Key` is now declared in the OpenAPI document.** The header has worked since caller-provided keys shipped, but it lived only in prose — it was never listed among the parameters of `POST /run`, so a client generated from `openapi.json` had no way to send it. Declaring its companion `X-LLM-Base-URL` is what made the omission visible.
- **Five operator environment variables are now in the self-hosting reference.** `SKRUN_RUNNERS_APP`, `SKRUN_ALLOW_SERVER_KEY_CUSTOM_BASE_URL`, `SKRUN_ALLOW_LOCAL_MODEL_HOSTS`, `SKRUN_ALLOW_LOCAL_WEBHOOKS` and `SKRUN_PRIMARY_FAILOVER_MS` are read by the server but were absent from the environment table. The first three are fail-closed security opt-ins, so an operator who ran into the refusal had no documented place to find the flag that lifts it — only the refusal message itself. The two model-endpoint opt-ins are also in `.env.example` now.
- **Reference docs brought back in line with private-by-default and vendor-agnostic Postgres.** The permission table in `docs/api.md` still described the pre-`visibility` model — *"Run any agent: anyone (marketplace model — `bob` can run `alice/my-agent`)"*, *"List agents: anyone (public listing)"*, and verification as the namespace owner's call. All three were wrong, and contradicted by other sections of that same file. `docs/concepts.md` carried the same "invocation is intentionally cross-namespace" claim two screens above its own correct private-only section. `docs/api.md`'s LLM-key priority listed only caller → server, omitting the creator-attached tier, and opened by saying runs use the server's key "by default" — the opposite of the hosted posture. `packages/sdk/README.md` showed `setVisibility(agent, "public")` as a working call; it returns `400 PUBLIC_VISIBILITY_DISABLED`. `docs/agent-yaml.md` pointed operators at the removed agent-level `PATCH …/verify`. Three pages still named Supabase as *the* production backend, which `PostgresDb` replaced. Four cross-file links (`api.md#verify-an-agent`, `#files-api`, `#post-run`, `#post-runs-execute-an-agent`) pointed at headings that do not exist. No behaviour change — the code was already right in every case; the docs described an older one.
- **`agent.yaml`'s `state.ttl` is now documented as declarative.** The field is parsed and validated (default `30d`), and both `docs/agent-yaml.md` and `docs/concepts.md` presented it as a retention window — but nothing expires state on that schedule: KV state persists until the agent is deleted. Both pages now say so plainly and point to `type: none`, or clearing keys from the agent itself, for anything that should not accumulate. Enforcing the window is tracked as separate work.

### Security
- **The server now blocks request forgery (SSRF) by the resolved IP address, not just the hostname.** Outbound requests the server makes on your behalf — webhook delivery, fetching a file-input URL, and connecting to a remote MCP server — are checked against the address a hostname actually resolves to, and the connection is pinned to that validated address, so a name that resolves to a private or reserved IP (cloud metadata such as `169.254.169.254`, loopback, link-local) is refused before any data is sent, including across a redirect. Previously only the hostname string was checked, which a DNS name pointing at an internal address could slip past (reachable via a file-input URL on `POST /run` for an agent with unrestricted `allowed_hosts`). Non-HTTP(S) URLs are also rejected.
- **Secrets no longer reach untrusted skill code.** On the self-host / local (in-process) runtime, an agent's script process previously received every `SKRUN_*` environment variable — which included the encryption master key that decrypts creators' stored LLM keys. Script processes now receive only the documented contract variables. Separately, the dependency installer (pip / npm, and the postinstall scripts of untrusted dependencies) no longer receives the full server environment: secret-shaped variables (API keys, tokens, the encryption key, S3 access keys, the database URL) are stripped, while the operating-system variables installers need (PATH, HOME, proxy and CA-certificate settings) are kept. The cloud runtime was never affected (its sandbox has a curated environment).
- **Webhook delivery to private hosts is fail-closed.** The `webhook_url` validation no longer relaxes itself when `NODE_ENV` isn't `production` — a self-host that didn't set `NODE_ENV=production` was previously left with no webhook SSRF protection at all. Private / non-HTTPS webhook targets are refused by default; set `SKRUN_ALLOW_LOCAL_WEBHOOKS=true` to allow `http://localhost` targets for local testing only (documented in `.env.example` and `docs/api.md`).
- **Operator signup allowlist (`SKRUN_ALLOWED_GITHUB_USERS`).** A new operator opt-in restricting who may create an account / sign in via GitHub OAuth — for a **private** self-host instance or a **curated closed beta**. Comma-separated `username` (case-insensitive) or `id:<NNN>` (the immutable GitHub id, rename-proof); when set, only listed accounts pass the OAuth callback gate (**every** login, web **and** `skrun login` — a non-listed device login is rejected and its pending code terminated), and anyone else gets a generic "not authorized" page (no account created, no echo of the rejected identity). **Unset = open signup** (the public-cloud default; non-breaking). Read from the env (a secret / config — never editable from inside the app); it gates the **account root** only and does not change what a delegated `sk_live` key can do. See `docs/self-hosting.md` → "Mode 2: GitHub OAuth".
- **`dev-token` admin is now an explicit, fail-secure opt-in (`SKRUN_DEV_AUTH`).** Previously the registry granted admin to any `Bearer dev-token` caller whenever GitHub OAuth was not configured — which silently turned any reachable no-OAuth deployment into an open admin endpoint (and the dashboard auto-authenticated a visitor as admin against it). The shortcut is now gated behind `SKRUN_DEV_AUTH` (default **off**); `pnpm dev:registry` enables it for localhost, and the api-server **refuses to boot** if it is enabled in production without OAuth. The dashboard now sends unauthenticated visitors to the login screen on such instances (it no longer renders a placeholder admin profile). Configure GitHub OAuth (or API keys) for any reachable deployment.
- **`DELETE /api/files/:id` now enforces input-file ownership.** The endpoint already required authentication and refused agent outputs, but it skipped the per-caller ownership check its `GET` siblings perform — any authenticated user could delete another user's uploaded input file by id (cross-user deletion / IDOR). It now returns `403 FORBIDDEN` when the input file belongs to a different user. The earlier ownership hardening covered only the file-content read endpoints; this extends the same check to the delete path.
- **An agent's `model.base_url` is validated before it becomes the destination of a credentialed request.** It was accepted as any syntactically valid URL and handed to the provider SDK, which attaches `Authorization: Bearer <key>` to it. Because the model loop runs in the server process rather than in the agent sandbox, the agent's own `allowed_hosts` egress rules never applied to it — so an agent could make the component holding every credential issue requests to a host of its choosing, including internal and cloud-metadata addresses. Two checks now apply on every key tier: the URL must be `http(s)` and must not name a private or reserved address (set `SKRUN_ALLOW_LOCAL_MODEL_HOSTS=true` for a local Ollama / vLLM / LocalAI endpoint), **and** the request goes through the same connect-time guard the webhook, file-input and MCP paths already use, which validates every address a hostname resolves to before the socket opens. The two are not redundant: a literal such as `http://127.0.0.1/` is stopped only by the first, and a public hostname resolving to an internal address only by the second. See the Breaking section for the credential half.
- **`skrun login` no longer runs a shell command built from the registry's response.** The interactive login opened your browser by interpolating the verification URL — a value chosen by whatever registry the CLI points at — into a shell command string. A hostile or intercepted registry could therefore run arbitrary commands on the developer's machine (the CLI's registry URL has no TLS requirement and defaults to plaintext). The URL is now passed to the OS opener as an argument with no shell anywhere on the path, and non-`http(s)` schemes are refused outright. This was the only shell-string command construction in the codebase.
- **Scan-push no longer accepts a sibling directory that shares the agents-directory prefix.** `POST /api/agents/scan/:name/push` (the dashboard's "push from a local directory" path, active only when `SKRUN_AGENTS_DIR` is set) checked containment with a prefix comparison that lacked a trailing separator, so `<agents-dir>-backup` satisfied it and its contents were packaged as the caller's agent. The name is now validated as a single path segment, as every registry route already does, and containment is compared with the separator.
- **The runtime image installs `mise` from a pinned, checksum-verified binary, and its base image is digest-pinned.** The Dockerfile piped a remote installer script into a shell (`curl https://mise.run | sh`) with no version, checksum or signature, so a compromise of that host or of the build network would land arbitrary code in the base layer shared by the sandbox runner **and** the self-host API server. It now downloads the pinned release binary and verifies its SHA-256 before making it executable — there is no piped shell left. `ubuntu:24.04` is pinned by digest as well, so the same commit no longer builds on a moving base.
- **Dependencies: 16 outstanding high-severity advisories, none.** Including `undici`, which is the transport the SSRF guard above runs on, and `@hono/node-server`, which carried a static-file path traversal while the dashboard is served through it. No major version bump was required — every advisory was patched within the current major. The transitive copies reached through `@modelcontextprotocol/sdk` are pinned forward too (`@hono/node-server`, `body-parser`), so the fix is not limited to the direct dependency — bumping only the direct one left a second, older copy of the same package carrying the same advisory. The single advisory left is `esbuild`'s development-server file read, which reaches no production path: esbuild is a build-time dependency of the test runner, and its dev server is never started.
- **Agent bundles are integrity-checked on download.** The registry now stores a SHA-256 checksum of each bundle at push and verifies it on every pull — both the run path and the `GET /pull` download. A bundle that has been tampered with in storage is refused with a `500` instead of being executed as agent code. Bundles pushed before this release are verified once their checksum is backfilled on the next server start.
- **Rate limiting now coordinates across server instances.** The per-IP limit on `push` and `run` was counted per-process, so a multi-instance deployment could be bypassed by spreading requests across instances; it now uses a shared Redis store when `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` are set (single-instance self-host keeps the in-memory limiter — no Redis required), falling back to per-instance limiting on a Redis outage rather than failing open or closed. `X-Forwarded-For` is trusted for the client IP only when `SKRUN_TRUST_PROXY` is set, so the limit key can't be spoofed on a directly-exposed deployment.
- **Provider error messages can no longer leak an LLM key into the run record or logs.** A provider 4xx (e.g. a `401` on a bad key) can echo a fragment of the key in its message. That message was written **raw** to the `runs.error` column (readable via `GET /api/runs/:id`) on the streaming and webhook failure paths, and logged as a free-text string by the runtime's model-fallback path — both bypassing the structured-field redaction. They are now sanitized against the active caller **and** creator key values before reaching the database or the log drain, hardening the pre-existing caller-key path as well as the new creator key.
- **The CLI login no longer passes your API key through a URL.** `skrun login` previously delivered the `sk_live` key to the terminal via a `?token=…` redirect to a local loopback server, exposing it to browser history, the `Referer` header, and access logs. It now uses an OAuth 2.0 Device Authorization Grant (RFC 8628) with PKCE: the CLI polls the server and receives the token **only in a response body, never a URL**. The local loopback server is gone (which also closes an unvalidated-callback token-injection vector), so login works over SSH / in containers too. Device codes are short-lived, single-use, and rate-limited, the verifier never leaves the CLI, and the browser consent page carries a double-submit CSRF token + a device-code-phishing warning.
- **Sandbox runner egress is now contained on IPv6 as well as IPv4.** The cloud sandbox's egress allowlist was enforced with `iptables` (IPv4) only; on Fly.io the runner sits on an IPv6 6PN private network, so IPv6 egress was unrestricted — a sandboxed agent could reach sibling runners, the api-server, or Fly internals over IPv6, bypassing the agent's declared `allowed_hosts`. The runner entrypoint now installs a symmetric `ip6tables` policy (default-DROP output + loopback + ESTABLISHED,RELATED + the IPv6 DNS resolver + the AAAA records of each allowed host), and the short-TTL DNS re-resolver maintains the v6 rules alongside the v4 ones. Only `SKRUN_RUNTIME=flyio` runners were exposed — the default `local` runtime has no sandbox machine and is unaffected.
- **Resolved private and link-local addresses are dropped before the egress allow.** The app-layer host check only blocked literal private hostnames; an allowed host that resolved (or re-resolved on its short TTL) to a private, loopback, link-local, or carrier-grade-NAT address — `169.254.169.254`, `100.64.0.0/10`, `fc00::/7`, and the like — was still added to the egress ruleset, a DNS-rebinding path toward cloud metadata and internal services. Each resolved address now passes through a private-IP filter (range checks mirroring the app-layer network policy) before the runner allows it, on both the IPv4 and the new IPv6 path.
- **The sandbox runner control RPC is now authenticated per run.** The harness-to-runner RPC (`/init`, `/tool`, `/outputs/collect`, `/outputs/file`) trusted 6PN network isolation and accepted any caller; combined with the IPv6 egress gap above, one runner could drive another runner's RPC across tenants. The harness now mints a per-run 256-bit token, injects it into the machine at spawn, and the runner enforces it as a timing-safe `Bearer` credential on every control route (the `/healthz` boot probe stays open). Enforcement engages only when the token is present, so a rolling deploy — runner image before api — stays compatible.
- **`skrun pull` now bounds how much a bundle can decompress, and refuses escaping entries.** The download-and-extract path had no ceiling on decompressed size — a small, maliciously crafted archive could expand to exhaust memory on the machine running the CLI. It now enforces the same decompression cap the server already applied (default 50 MB, tunable via `BUNDLE_MAX_DECOMPRESSED_MB`), and both the CLI and the server reject a symbolic-link entry or a path that resolves outside the extraction directory — the server skips it (so one malformed bundle can't stall a shared instance), the CLI fails loudly.

## [0.8.0] - 2026-05-22

### Breaking
- **Registry reads now require auth and filter by ownership.** `GET /api/agents`, `/:ns/:name`, `/:ns/:name/versions`, `/:ns/:name/stats`, and `/:ns/:name/pull` (+ `/pull/:version`) return `404` to non-owner non-admin callers (indistinguishable from "doesn't exist"). Running an agent (`POST /run`) stays cross-namespace. `dev-token` self-host is unaffected (auto-admin); OAuth and `sk_live_*` callers must pass `Authorization: Bearer <token>`. SDK + CLI client methods updated to send the header.
- **`agent.yaml`'s `name` is now slug-only** (was `<namespace>/<slug>`). The registry assigns the namespace at push time from your auth context. Migration: `name: dev/email-drafter` → `name: email-drafter`. The registry URL form `<namespace>/<slug>` is unchanged. CLI `--namespace` flag and interactive prompt removed. Dashboard Import dialog now uses explicit form fields (fixes a long-standing filename mis-parse on multi-hyphen slugs).
- **Verification is now per-version + admin-only.** The legacy `PATCH /api/agents/:ns/:name/verify` is removed; use `PATCH /:versions/:version/verify`. SDK `client.verify()` → `client.verifyVersion()`. Existing `verified=true` rows are reset on upgrade — promote an admin (`UPDATE users SET role='admin' WHERE username='you'`) then re-verify each version. Pinned callers are protected: pushing a new version doesn't touch prior verified versions.
- **`POST /run` now returns `403 AGENT_NOT_VERIFIED` for unverified versions.** Runtime refuses before any LLM call, MCP connection, or file alloc. Catch typed via `SkrunNotVerifiedError` in the SDK. The old soft `agent_not_verified_scripts_disabled` warning is gone.
- **File-content endpoints now require auth + ownership.** `GET /api/files/:id`, `GET /api/files/:id/content`, and `GET /api/runs/:run_id/files/:filename` were public before — any caller could fetch any file by id. They now return `401` without auth, `403` for non-owners.
- **`DELETE /api/agents/:ns/:name` and `DELETE .../versions/:v` gain admin override.** Authorization is now "namespace owner OR admin" (was namespace-only). Lets operators clean up squatter / abusive agents across namespaces.
- **Webhook delivery now requires `WEBHOOK_SIGNING_KEY`.** The hardcoded fallback (forgeable from the public source) is removed; the runtime throws if no key is configured. Set `WEBHOOK_SIGNING_KEY` in your environment — see `.env.example`.
- **`CORS_ORIGIN` is now required in production.** When `NODE_ENV=production`, the API fails fast at startup if unset (no implicit `*` fallback). Set e.g. `CORS_ORIGIN=https://app.example.com`. Dev still defaults to `*`.

### Added
- **`skrun whoami`** — prints the current CLI identity (namespace + registry URL).
- **`skrun verify` / `skrun unverify` / `skrun run` CLI commands.** Closes the long-standing gap where `push` had no symmetric `run` in the CLI. `skrun run <ns>/<name>[@<v>]` invokes an agent with input via `-i '<json>'` (inline), `-f <file>` (file path), or `--stdin` (pipe); prints JSON to stdout; renders only `<code>: <message>` on error (never the raw response body). `skrun verify <ns>/<name>@<version>` mints admin trust on a specific version; `skrun unverify` revokes. Admin gate enforced server-side — `dev-token` is auto-admin so local-dev flows just work.
- **`SkrunNotVerifiedError` typed SDK class.** Subclass of `SkrunApiError`. `SkrunApiError.fromResponse` now dispatches on `error.code` to typed subclasses — consumers catch with `if (err instanceof SkrunNotVerifiedError)` instead of string-comparing `err.code`. Extensible dispatch table for future typed codes.
- **Per-version trust surfaces on the dashboard.** Versions table on agent-detail gains Status + Actions columns (per-row badge + Verify/Unverify buttons for admins). Playground Run button is disabled with an amber banner when the selected version is unverified. Listing badge sources from `latest_version_verified`. Delete button hidden for non-owner non-admin viewers.
- **Structured log on every verify/unverify.** Pino `info` line `event: "agent_version_verify"` carrying `{actor, target, action, timestamp}` — the forensic trail until the audit-log UI ships. Pipe the registry's stdout to your log aggregator and filter on the event name.
- **Run output validation against the declared schema.** At the end of every run, the runtime checks the LLM's final JSON output against the agent's `outputs` declarations (top-level keys + types; extra keys allowed; nested arrays/objects accept any internal shape). On mismatch, an `output_validation_warning` event is emitted and the runtime issues one isolated repair call to the LLM with the validation errors. If the retry succeeds, the run terminates normally via `run_complete` with the corrected output and summed token usage across both attempts; if it still fails (schema mismatch or non-JSON), the run terminates via `run_error` with `error.code: OUTPUT_SCHEMA_INVALID` instead of returning a broken payload. Skipped when an agent declares no outputs.
- **Downloadable run artifacts in the dashboard.** Both the live playground and the run-detail page render a Files block listing every artifact the agent produced (`run_complete.files[]`) with a per-file Download button. Downloads go through `/api/files/:id/content` with the caller's auth.

### Changed
- **Tool failures surface as `tool_call_error` SSE events.** When a tool returns `is_error: true`, the runtime emits a new informational event before the existing `tool_result`, carrying the tool name, the error message, and an optional structured `code` parsed from `[CODE]` prefixes (e.g. `[SCRIPT_DEPS_INSTALL_FAILED]`). The `tool_result` still flows back to the LLM normally — recovery decisions (retry, fallback, give up) stay with the LLM. Aligned with the permissive default in AWS Bedrock AgentCore, Claude Managed Agents, and Google Vertex Agent Builder. The dashboard renders these events in red with a `(LLM still received this; run continues)` subtitle.
- **Playground JSON-mode Attach button removed.** It uploaded files to the unified namespace and pasted a `{type:file, source:id}` ref into the textarea, but had no way to know which input field expected the file — agents with multiple file inputs ended up with refs in the wrong slot. JSON mode now renders a small hint pointing to Form mode (which wires the file_id into the correct input slot automatically) for agents that declare file inputs.

### Fixed
- **Supabase `getLatestVersion` non-deterministic tie.** Two rows with identical `pushed_at` (same-millisecond pushes) returned an arbitrary winner — security-relevant now that per-version verify gates on the resolved version. Added `id DESC` tiebreaker after `pushed_at DESC` (matches SQLite's `rowid DESC` behaviour).
- **Dashboard hides the Verify button for non-admin viewers.** Reads `user.role` from `GET /api/me`; missing role is treated as `'user'` (least-privilege). Per-version Verify/Unverify buttons in the versions table follow the same rule.
- `GET /api/agents/:namespace/:name` now returns real `run_count` and `token_count` (was hardcoded to `0`, surfacing misleading stats in the dashboard and CLI).
- **Tool scripts now spawn with `cwd` set to the agent bundle root.** Previously they inherited the registry's own cwd, so agents that referenced relative paths in their inputs (e.g. `./fixtures/sample.csv`) failed silently when called from a different working directory. Agents reading bundled fixtures now work out of the box.
- **Node script-dep install reliable on Windows.** Agents shipping a `package.json` (with or without a lockfile) had previously tripped Node's CVE-2024-27980 mitigation when resolving `pnpm` / `npm` / `yarn` directly (the actual executables are `.cmd` shims on Win32). The runtime now goes through the OS shell on Windows so the shim resolves cleanly. Python install path unchanged.

### Security
- **Cross-tenant run leakage fixed.** `GET /api/runs` now filters by the authenticated user's id (was instance-wide — any user saw every other user's run input/output payloads). Latent on single-user self-host; would have shipped broken on cloud.
- **Cross-tenant run-detail access fixed.** `GET /api/runs/:id` now returns `403` for non-owners (was reachable by any authenticated user via id).
- **IPv6 SSRF bypass closed.** Network allowlist now blocks IPv4-mapped IPv6 (`::ffff:*`, including bracketed URL form) and link-local IPv6 (`fe80:*`). Closes the AWS metadata reach via `http://[::ffff:169.254.169.254]/`.
- **Webhook delivery target validated in production.** When `NODE_ENV=production`, `POST /run` refuses `webhook_url` values resolving to private/reserved addresses (private IPv4, link-local IPv6, IPv4-mapped IPv6, IPv6 loopback — including AWS IMDS `169.254.169.254`). Dev mode bypasses this so local `http://localhost:NNNN/...` callbacks remain available for testing.
- **Gzip-bomb defense on bundle decompression.** Bundle extraction now caps the decompressed buffer at 50 MB by default. Configurable via `BUNDLE_MAX_DECOMPRESSED_MB` for operators with legitimately larger artefacts.
- **Spawned scripts no longer inherit server secrets.** Agent script processes previously received the full `process.env` spread, leaking `*_API_KEY`, `WEBHOOK_SIGNING_KEY`, `DATABASE_URL`, etc. Now strict allowlist: `PATH`, `HOME`, temp/locale vars, Python paths, all `SKRUN_*` vars, and conditional `NODE_PATH`.
- **Symlink path traversal closed.** Output collection now skips symlinks (logged as `symlink_rejected`); file resolution adds a defense-in-depth `realpath` check. Closes `ln -s /etc/passwd` exfil via `/api/files/:id/content`.
- **Security headers on every response.** `X-Frame-Options: DENY`, HSTS 2-year + `includeSubDomains` + `preload`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: cross-origin` (so the dashboard can load `/api/files/:id/content` cross-host on cloud). CSP deferred to a follow-up.
- **LocalStorage path-traversal closed + namespace/name validation.** Resolved paths now asserted inside `baseDir` (defangs the `/tmp/storage` vs `/tmp/storage-attacker` startsWith collision). Registry routes also gate `namespace` and `name` path params on `^[a-z0-9-]{1,64}$` at the boundary.

### Internal
- `pnpm dev:registry` and `pnpm test:e2e:live` now spawn Node with `--use-system-ca`. Fixes `unable to verify the first certificate` on Windows machines where an antivirus/firewall installs a MITM root or where the bundled CA store has drifted. Linux/macOS unaffected.
- `.env.example` reorganized into 4 explicit sections (LLM keys, Cloud/Production-required, Storage/DB, OAuth, Runtime advisory limits). The 2 newly-required-in-production vars (`WEBHOOK_SIGNING_KEY`, `CORS_ORIGIN`) are explicit at the top; `BUNDLE_MAX_DECOMPRESSED_MB` documented (default 50 MB); previously-undocumented existing vars surfaced (`DATABASE_URL`, `SUPABASE_KEY`, `GITHUB_CLIENT_ID`/`SECRET`).
- `docs/api.md` gets a top-level "Breaking changes in v0.8.0" summary table. `openapi.ts` enriched: `runAgent` description notes the `WEBHOOK_SIGNING_KEY` requirement; the `webhook_url` doc spells out the private-host refusal + dev-mode bypass.
- Internal refactors in `packages/api/src/routes`: extracted `persistRunCompletion` (DRY for the 3 run-completion sites in `run.ts`) and `dispatchRegistryError` (DRY for 9 `RegistryError` catch blocks). `RegistryError.status` is now typed as a `400 | 403 | 404 | 409 | 500` union. `UserContext.role` is exposed via `GET /api/me` so the dashboard can render admin-only UI.
- Hardened the `sync-public` GitHub workflow against shell injection — `commit_message` now passes through an `env:` mapping rather than being inlined into the `run:` block.
- Script `execFile` now uses an explicit 5 MB `maxBuffer` cap (was the implicit 1 MB Node default). Overflow produces a clear "buffer cap exceeded — truncate or write to `SKRUN_OUTPUT_DIR`" message instead of the opaque `stdout maxBuffer length exceeded`.
- DB `updateRun` failures during `/run` lifecycle (SSE/webhook/sync complete + error) now log at `error` level with `event=db_update_failed` (was silent `.catch(() => {})`, leaving stuck `running` runs undiagnosable).
- SQLite schema now declares `FOREIGN KEY` constraints on ownership and run-history chains (matching Postgres). Ownership uses `ON DELETE CASCADE`; `runs.*` uses `ON DELETE SET NULL` so analytics rows survive parent deletion. On upgrade, an orphan pre-check refuses to migrate when dangling references exist, with a remediation `DELETE` hint.
- SQLite now declares `UNIQUE(agent_id, version)` on `agent_versions` (Postgres parity). The service-layer 409 `VERSION_EXISTS` guard is now backed by a DB-level invariant. Pre-existing duplicates fail the migration loud with a dedupe hint.

- **Script dependency resolution** — agents declare `package.json` (Node), `requirements.txt`, or `pyproject.toml` (Python) at the bundle root. Subsequent calls reuse the cache (< 5 ms path lookup). The hash is computed from manifest content only (`SHA-256(<ecosystem>\n<manifestKind?>\n<manifestContent>\n[lockfileKind?]\n[lockfileContent])`) — same manifest text on different hosts produces the same hash, so cache entries are shareable across machines. - **Lockfile auto-detection** for reproducible installs:

Triggers `pnpm install --frozen-lockfile --dir=<cache>` / `yarn install --frozen-lockfile --cwd=<cache>` / `npm ci --prefix=<cache>`. No lockfile → `npm install --prefix=<cache>` + `non-reproducible build` warning to install logs.
  - Python — precedence `uv.lock` > `poetry.lock` (with `pyproject.toml`). Triggers real `uv sync --frozen` (uv bootstrapped via `pip install uv`) or `poetry install --no-root` (`POETRY_VIRTUALENVS_CREATE=false` + `VIRTUAL_ENV=<cache>/venv` to reuse the pre-created venv). `pyproject.toml` without lockfile → `pip install <bundle>` (PEP 517, non-editable). `requirements.txt` is treated as already pinned.

- SDK `@skrun-dev/sdk`: `run()`, `stream()`, `runAsync()` accept `{ version?: string }` in their options. `SdkRunResult.agent_version` and `AsyncRunResult.agent_version` are now required fields. `RunStartEvent.agent_version` exposes the resolved version.
- OpenAPI schema: request body adds optional `version`; `RunResult` and `AsyncRunResult` require `agent_version`; new `VersionNotFoundResponse` schema; 404 on `POST /run` uses `oneOf(ErrorResponse, VersionNotFoundResponse)`.
- **Structured JSON logging** via pino in `@skrun-dev/runtime` and `@skrun-dev/api`. Every log line is valid JSON with `level`, `time`, `name`, `msg`, and run context (`run_id`, `agent`, `agent_version`). Replaces all ad-hoc `console.log/warn/error` + the Phase 1 `AuditLogger`. `LOG_LEVEL` env var (debug/info/warn/error, default: info) controls verbosity. `createLogger` exported from `@skrun-dev/runtime` for operators embedding the runtime.
- 25+ new tests total: 13 for tool input_schema (7 schema, 6 runtime) + 12 for version pinning (8 api, 4 sdk, 6 openapi, 2 e2e integration) + 4 for structured logs (logger output, child bindings, LOG_LEVEL filtering, callerKeys redaction).
